Cursor 实战指南：从 Tab 补全到 Agent 编排

发表于2026-05-29|更新于2026-07-25|AI
|浏览量:

初识 Cursor

Cursor 是什么

Cursor 是一款基于 VS Code 的 AI 原生 IDE，由 Anysphere 公司开发。它把大语言模型深度嵌入到编码工作流的每一层：从单行 Tab 补全，到跨文件 Agent 自主编程，再到云端后台 Agent 和自动化流水线

和 GitHub Copilot 这类「插件式 AI 辅助」不同，Cursor 从架构上就是围绕 Agent 设计的。2026 年的 Cursor 3.0 更是把界面重心移到了 Agents Window，支持本地、WorkTree、云端、Remote SSH 等多环境并行运行 Agent

如果你已经在做 Vibe Coding，Cursor 大概率是你绕不开的工具；如果你希望从「跟着感觉写」进化到 Agentic Engineering，Cursor 提供的 Rules、Skills、Hooks、MCP 正是搭建 Harness（驾驭工程）的基础设施


Cursor 的本质是 VS Code + AI Agent 运行时。它保留了 VS Code 的编辑器体验、插件生态和快捷键习惯，同时在底层接入了多种大语言模型，并给 AI 配齐了读文件、改代码、跑终端、连外部工具等「手脚」

你可以把 Cursor 理解成三层的叠加：

  1. 编辑器层：熟悉的代码编辑、Git、调试、终端
  2. AI 交互层：Tab 补全、Inline Edit、Chat、Agent 等多种交互模式
  3. Harness 层：Rules、Skills、Hooks、MCP、Commands——约束 AI 行为的工程化配置

和 Claude Code、Windsurf、GitHub Copilot 相比，Cursor 的差异化在于 Agent 能力的完整度 和 Harness 生态的丰富度。同一套 Rules 和 Skills 可以跨项目复用，MCP 让 Agent 能连数据库、GitHub、Slack 等外部系统，Hooks 能在 Agent 执行前后自动触发检查流程


下载与安装

Cursor 全平台支持 Windows、macOS、Linux，官网下载地址：

  • 官网：https://cursor.com/
  • 下载页：https://cursor.com/download

安装过程和 VS Code 类似，双击安装包一路下一步就行。如果你之前用 VS Code，Cursor 首次启动时会提示 导入 VS Code 配置（扩展、快捷键、主题等），建议直接导入，迁移成本几乎为零


账号与订阅

Cursor 需要登录账号才能使用 AI 功能。免费版有有限的 Agent 请求额度，Pro 版（约 $20/月）提供更高的请求上限和更多高级功能（Background Agent、更多模型选择等）

Team / Enterprise 版面向团队，提供集中计费、隐私模式、Admin 管控等能力。个人学习阶段免费版或 Pro 版就够用了

界面与交互模式

界面概览

Cursor 3.0 之后有两套主要界面：

  • Editor（编辑器模式）：传统的 IDE 布局，适合边写代码边和 AI 对话
  • Agents Window（智能体窗口）：以 Agent 为中心的新界面，适合管理多个并行 Agent、云端 Agent 和 Automations

常用快捷键（Windows）：

操作 快捷键
打开 Agent 面板 Ctrl + I
Inline Edit（行内编辑） Ctrl + K
打开命令面板 Ctrl + Shift + P
切换 Agent 模式 在 Agent 面板内切换，或 Shift + Tab 进入 Plan Mode

五种核心交互模式

Cursor 的 AI 能力不是一个「Chat 框」能概括的，它提供了由浅入深的五层交互模式。理解它们的边界，是高效使用 Cursor 的第一步

模式 能力边界 典型场景 类比
Tab 补全 预测下一行/下一段代码 日常编码、快速补全 超级自动补全
Inline Edit 选中代码后 AI 原地修改 重构一个函数、改命名 局部手术刀
Chat（Ask） 只读，解释代码、回答问题 理解陌生代码库、学习 API 带代码上下文的 ChatGPT
Agent 读写文件、跑终端、自主迭代 实现功能、修 Bug、跑测试 自主干活的实习生
Plan Mode 先出方案再执行 复杂需求、架构变更 先画图纸再施工


Tab 补全

Tab 补全是 Cursor 最轻量、最高频的能力。你在写代码时，Cursor 会根据当前文件和项目上下文，灰色预览接下来可能要写的代码，按 Tab 接受

它的特点是：

  • 零打断：不需要打开 Chat，写代码的节奏不会被打断
  • 上下文感知：不只看当前行，还会参考项目里其他相关文件
  • 多行补全：有时一次能补全整个函数体

Tab 补全适合 你已经知道要写什么、只是懒得敲 的场景。不要指望它帮你做架构决策


Inline Edit（Ctrl + K）

选中一段代码，按 Ctrl + K，输入自然语言指令，AI 会在原地修改选中的代码。修改结果以 diff 形式展示，你可以逐块 Accept 或 Reject

Inline Edit 适合 改动范围明确、不需要跨文件 的场景，比如：

  • 「把这个函数改成 async/await」
  • 「给这个类加上 JavaDoc 注释」
  • 「提取这个方法到工具类里」


Chat（Ask 模式）

Ask 模式是 只读 的。AI 可以读取你的代码文件来回答问题，但不会修改任何文件、不会运行终端命令

适合这些场景：

  • 「这个项目的认证流程是怎么走的？」
  • 「这段正则表达式匹配的是什么？」
  • 「Compare 一下这两种实现方案的优劣」

Ask 模式是 理解代码库 和 技术调研 的首选，也是 Plan Mode 和 Agent Mode 的前置步骤——先搞懂再动手


Agent 模式

Agent 模式是 Cursor 的 核心能力。在这个模式下，AI 不再只是「给建议」，而是像一个自主的编程助手：

  1. 感知：搜索和读取相关文件
  2. 思考：分析现状，规划实现方案
  3. 行动：编辑代码、创建文件、运行终端命令
  4. 观察：检查命令输出、Linter 报错、测试结果
  5. 循环：根据结果继续修改，直到任务完成或需要你介入

Agent 模式下，你描述 目标 而不是 步骤。与其说「在第 42 行把变量名改成 userId」，不如说「重构认证模块，让 Token 刷新自动完成，确保现有测试仍然通过」——Agent 会自己找文件、做计划、执行和验证


Plan Mode

Plan Mode 是 Agent 的「先想后做」模式。按 Shift + Tab 或在模式切换中选择 Plan，Agent 会先产出一份 可审查的执行计划（涉及哪些文件、分几步、每步做什么），你确认或修改后再开始执行

Plan Mode 的价值在于 把错误拦截在执行之前。Agent 方向错了，在 Plan 阶段改只需要 10 秒；如果已经改了 20 个文件，回滚就痛苦了

推荐在以下场景使用 Plan Mode：

  • 跨 3 个以上文件的功能开发
  • 涉及数据库迁移或 API 变更
  • 你不完全确定最佳实现路径
  • 想对比多个实现方案（Cursor 支持 Parallel Agents 并行出多份 Plan）

上下文管理

上下文是什么

上下文（Context）是 AI 在回答和编码时能够参考的所有信息。上下文越精准，AI 的输出越靠谱；上下文越臃肿，成本越高、效果反而可能下降

Cursor 中的上下文来源包括：

  • 当前对话的历史消息
  • 你通过 @ 引用的文件、文件夹、代码片段
  • 项目中的 Rules、Skills、AGENTS.md
  • Agent 自主搜索和读取的文件
  • MCP 工具返回的外部数据


@ 引用

在 Agent 或 Chat 对话框中输入 @，可以精确引用上下文：

引用类型 作用 示例
@文件 引用特定文件 @src/auth/service.ts
@文件夹 引用整个目录 @src/components/
@Codebase 让 AI 搜索整个代码库 适合「这个功能在哪实现的？」
@Docs 引用 Cursor 内置或自定义文档 查框架 API
@Web 搜索互联网 查最新文档或报错信息
@Git 引用 Git 历史 对比分支差异
@规则名 手动激活某条 Rule @typescript-standards

Cursor 3.0 之后，Agent 模式下的 自主上下文收集 能力已经很强——你不手动 @ 文件，Agent 也会自己搜索相关代码。但弄清楚 @ 引用仍然有价值，尤其是你想 强制 AI 关注某个特定文件 的时候


Token 与成本控制

Cursor 的 AI 功能按 Token 计费（包含在订阅额度内）。几个实用的省钱技巧：

  • 小任务用 Tab / Inline Edit，别动不动就开 Agent
  • Ask 模式做调研，搞清楚了再切 Agent 执行
  • 复杂任务先 Plan，避免 Agent 走错方向白烧 Token
  • 适时开新对话，避免上下文无限膨胀
  • Rules 保持精简，alwaysApply: true 的规则每次对话都会加载
  • 对话框附近的 Token 用量指示器 可以帮你感知当前上下文大小

Harness 工程化配置

Rules 规则

Rules 是 Cursor 的 项目级 AI 指令，告诉 Agent 你的编码规范、技术栈偏好、禁止事项等。有了 Rules，你不需要每次对话都重复「用 TypeScript strict 模式」「不要用 var」「API 返回统一 Restful Response」

存放位置

文件格式

Rules 使用 .mdc 格式（Markdown + YAML frontmatter）：

激活方式

方式 配置 说明
始终生效 alwaysApply: true 每次对话都加载
文件匹配 globs: **/*.ts 编辑匹配文件时自动激活
手动引用 对话中 @规则名 按需加载
AI 自主决定 只写 description Agent 根据任务相关性判断

旧版 .cursorrules

Cursor 早期使用项目根目录的 .cursorrules 单文件。现在官方推荐迁移到 .cursor/rules/*.mdc 多文件格式，好处是：

  • 按文件类型分规则，避免所有规则一股脑加载
  • 可以用 Git 管理、团队共享
  • 支持更精细的激活条件

AGENTS.md

AGENTS.md 是跨工具的开放标准，专门写给 AI 看的项目说明。Cursor 会自动识别项目根目录下的 AGENTS.md，内容包括：

  • 构建和启动命令
  • 测试运行方式
  • 代码风格规范
  • 项目结构说明

AGENTS.md 和 Rules 互补：AGENTS.md 偏 项目事实（怎么构建、怎么测试），Rules 偏 行为约束（怎么写代码、什么不能做）

Skills 技能

Skills 是比 Rules 更 结构化、更模块化 的 AI 指令单元。每个 Skill 是一个目录，核心是 SKILL.md 文件，教 Agent 如何完成特定任务

存放位置

类型 路径 作用域
个人 Skill ~/.cursor/skills/skill-name/ 所有项目可用
项目 Skill .cursor/skills/skill-name/ 当前项目，可 Git 共享

注意：~/.cursor/skills-cursor/ 是 Cursor 内置 Skill 目录，不要在这里创建自定义 Skill

文件结构

SKILL.md 示例

Skills 和 Rules 的区别：

特性 Rules Skills
粒度 编码规范、项目约定 完整工作流（Review、Deploy、Debug）
触发 自动激活或手动 @ Agent 根据 description 自主发现

类比 员工手册 操作 SOP

Hooks 钩子

Hooks 是 Cursor 的 事件驱动自动化机制。当 Agent 执行特定动作时（生成代码、运行命令、编辑文件），Hook 会自动执行你预设的脚本或检查

常用 Hook 事件

事件 触发时机 典型用途
sessionStart 会话开始 注入项目上下文
beforeShellExecution 运行终端命令前 拦截危险命令

Hooks 和 Skills 配合使用效果更好：Skill 定义「做什么」，Hook 定义「什么时候自动做」

MCP（Model Context Protocol）

MCP 是 AI 连接外部工具的 标准协议。通过 MCP，Cursor Agent 可以查询数据库、操作 GitHub、读取 Slack 消息、调用自定义 API 等

MCP vs A2A

别把 MCP 和 A2A 搞混：

  • MCP：AI 连接 工具和数据源（数据库、API、文件系统）
  • A2A：AI 智能体之间 互相通信协作（多 Agent 团队）

二者是互补关系。MCP 给 Agent 装「手」，A2A 让多个 Agent 能「对话」

高级能力

模型选择

Cursor 支持多种大语言模型，可以在 Agent 面板底部切换：

模型 特点 适用场景
Composer Cursor 自研，速度快 日常开发首选
Claude Sonnet / Opus Anthropic，推理强 复杂逻辑、架构设计
GPT-4o / o3 OpenAI，通用能力强 多语言项目
Gemini Google，长上下文 大代码库分析
Auto Cursor 自动路由 不想纠结选型时的默认选择

Auto 模式 是 Cursor 的模型路由器，会根据你的 Prompt 自动选择当前最优模型。日常开发推荐 Auto 作为默认，只在需要特定模型特性（比如 Claude 的长推理）时手动切换

并行 Agent 与 WorkTree

Cursor 支持 Parallel Agents——同时运行多个 Agent，各自在独立的 Git WorkTree 中工作，避免代码冲突

典型场景：

  • 让 3 个 Agent 分别出 3 份 Plan，你选最好的那份执行
  • 前端 Agent 和后端 Agent 同时开发，最后合并
  • 一个 Agent 写功能，另一个 Agent 写测试

WorkTree 给每个 Agent 分配独立的工作目录和分支，就像给每个 Agent 一间独立办公室。干完了再合并回主分支

Background Agent 与 Cloud Agent

Background Agent 让 AI 在后台自主运行，你不需要盯着屏幕等。任务完成后会通知你来验收

Cloud Agent 在 Cursor 云端 VM 上运行，你可以：

  • 关掉本地电脑，Agent 继续干活
  • 在 cursor.com/agents 网页端查看进度
  • 通过 GitHub、Linear 等集成触发 Agent

使用场景：

  • 「帮我把这 10 个 Issue 的 Bug 都修一遍，修完通知我」
  • 「给这个项目补全单元测试，覆盖率到 80%」
  • 「Review 一下这个 PR，有问题直接提 comment」

Cursor Automations

Automations 是 Cursor 的 触发式自动化——当某个事件发生时（Git Push、Slack 消息、定时任务），自动启动 Agent 执行预设工作流

典型 Automations：

  • PR 创建时：自动跑 Code Review
  • Push 到 main 时：自动更新 CHANGELOG
  • 每天 9:00：自动检查依赖安全漏洞
  • Slack 收到 Bug 报告：自动创建修复分支并开始修复

创建方式：在 Agents Window 中使用 /automate 命令，或在 Cursor 设置中打开 Automations 编辑器

Automations 把一次性的 Agent 对话变成了 可重复、可触发、可审计 的工程流程

Subagents 子代理

当 Agent 遇到大任务时，可以通过 Task 工具 启动 Subagent（子代理）并行处理子任务。每个 Subagent 有独立的上下文，互不干扰

Subagent 适合：

  • 同时审查代码库的不同模块
  • 并行搜索多个目录
  • 主 Agent 继续规划，子 Agent 去执行调研

Subagent 不适合有强依赖关系的任务（比如 B 必须等 A 的输出），因为子代理之间无法直接共享信息

与 Vibe Coding 的关系

从 Vibe Coding 到 Agentic Engineering

Cursor 是 Vibe Coding 最天然的载体，但要用好它，需要理解不同层次的协作方式：

层次 做法 Cursor 对应能力 适用场景
Vibe Coding 给一句话，AI 出代码，能跑就行 Tab + Inline Edit + 简单 Chat 小脚本、原型验证
Agentic Coding 让 Agent 自主规划执行 Agent Mode 功能开发、Bug 修复
Harness Engineering 用 Rules/Skills/Hooks 约束 Agent Rules + Skills + Hooks + MCP 团队项目、长期维护
Agentic Engineering 人做架构和验收，AI 做执行 Plan Mode + Review + Automations 企业级项目


推荐工作流

一个经过验证的 Cursor 高效工作流：

对于团队项目，建议在步骤 1 之前先配好：

  • .cursor/rules/ — 编码规范
  • AGENTS.md — 项目构建/测试说明
  • .cursor/skills/ — 团队工作流（Review、Deploy 等）
  • .cursor/hooks.json — 自动格式化、安全检查

最佳实践

提示词技巧

  • 描述目标，不是步骤：「重构认证模块支持 Token 自动刷新」优于「在第 42 行加一个 setInterval」
  • 给出约束：「不要改 public API」「保持向后兼容」「测试必须通过」
  • 提供示例：「参考 src/order/service.ts 的写法」
  • 分步交付：大任务拆成多个小对话，每个对话聚焦一个子目标

常见踩坑

问题 原因 解法
Agent 改了一堆不相关的文件 任务范围太大 用 Plan Mode 先收窄范围
Token 消耗过快 上下文膨胀 + Agent 循环过多 开新对话、用 /compact、小任务别用 Agent
生成的代码不符合项目风格 没有配置 Rules 创建 .cursor/rules/
Agent 声称测试通过但没跑 AI 的「知行脱节」 配置 Hooks 自动跑测试；用 Superpowers 等 Skill 框架
MCP 连接失败 环境变量未配置 / 服务未启动 检查 Settings → MCP 状态
并行 Agent 代码冲突 WorkTree 合并策略不当 先 Plan 再并行，合并前人工 Review

安全注意事项

  • 不要在 Rules、Skills、Prompt 中硬编码 API Key 或密码
  • Background / Cloud Agent 会访问你的代码仓库，注意 .env 等敏感文件是否被 .gitignore
  • 配置 beforeShellExecution Hook 拦截 rm -rf、git push --force 等危险命令
  • Enterprise 版提供 Privacy Mode，代码不会用于模型训练
  • MCP 连接外部服务时，遵循最小权限原则
